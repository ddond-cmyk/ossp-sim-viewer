3. 검증기 ↔ 작성자 왕복 기록

1차 검사에서 결함 5 · 경고 5가 나왔다. 셋으로 갈렸다.

3-1. 진짜 결함 2건 — 산출물을 고쳤다

위치결함수정
HDP-COM0106 항목 1선택 시 > 해당 영역 랜딩으로 이동 — 대상 화면ID 없음GNB 6종의 랜딩 화면ID 6개 전건 병기
HDP-BRD0103 항목 6해당 브랜드 상세로 이동 — 대상 화면ID 없음화면 ID : HDP-BRD0103 병기(같은 골격 재귀)
둘 다 「해당 ~로 이동」이었다. C절 규칙 17이 "「해당 페이지로 이동」만 쓰고 끝내지 않는다" 고 콕 집어 금지한 문형인데, 규칙을 알고 쓰면서도 두 번 썼다. 「해당」은 사람이 읽으면 자연스럽고 기계가 읽으면 미정의다.

3-2. 검증기 오탐 2건 — 검증기를 고쳤다

위치오탐 내용원인
HDP-COM0114 항목 2목록 즉시 갱신 — 페이지 재호출 없음「호출」을 부정문 안에서 잡았다
HDP-STR0102 항목 4같은 화면 안에서 본문 블록 전환 — 화면 이동 없음「이동」을 부정문 안에서 잡았다

둘 다 「이동을 안 한다」는 선언인데 「이동」으로 잡혔다. 탭 전환처럼 같은 화면 안에서 끝나는 동작을 명시하는 자리다 — 333(UI가이드정의)이 N-04 탭과 N-03 LNB를 별 컴포넌트로 판정한 근거("탭은 같은 화면 안에서 전환하고 LNB는 다른 화면으로 이동한다")가 여기서 문형으로 나타난다.

부정문 제외 + 동적 대상(직전 화면·유입경로) 허용을 추가했다.

3-3. 검사 단위 오류 1건 — 검증기를 고쳤다

HDP-BRD0103 항목 6에서 최대 6건 노출(불릿 1)과 6건 초과 시 > 상위 6건만 노출(불릿 2)이 다른 줄이라 초과 처리가 있는데도 결함으로 잡혔다.

속성 순서 규칙(C절 규칙 9) 자체가 이걸 두 줄로 갈라 놓는다 — ②노출 항목과 ④제한이 다른 순서 자리다. 그래서 검사 단위를 불릿에서 항목으로 올렸다.

규칙이 규칙을 어기게 만드는 구조였다. 문형 규칙(속성 순서)과 검사 규칙(불릿 단위)이 서로 맞지 않았다.

3-4. 경고 4건 — 산출물을 고쳤다

최대 N만 쓰고 초과 처리를 안 밝힌 항목 4건에 초과 처리를 넣었다.

위치추가한 처리
HDP-COM0106 항목 3 배너10개 초과 시 > Admin 등록 차단 처리
HDP-COM0106 항목 4 행사3건 초과 시 > 「전체 보기」 링크 노출
HDP-STR0102 항목 3 대표 이미지초과 등록 시 > 최신 1건만 노출 처리
HDP-STR0102 항목 7 행사3건 초과 시 > 「전체 보기」 링크 노출
초과 처리를 안 쓰면 개발이 임의로 정한다. 「최대 3건」만 있으면 4번째가 잘리는지 스크롤되는지 더보기가 붙는지 아무도 모른다.

4. 규칙 공백 (FAIL이 아니라 보완 대상)

검증기가 판정할 수 없어서 검사하지 않은 항목이다. 99-verifier.md 원칙 — "판정 불가(규칙 부재)면 FAIL이 아니라 「규칙 공백」으로 보고한다."

#공백왜 판정 불가인가보완 위치
1유형별 수직 구조 일치struct 문자열이 자유 서술이라 유형 사전의 구조와 기계 대조가 안 된다. H절 38-4가 요구하는 검사인데 못 했다유형 사전에 구조를 열거값으로 고정
2속성 순서 준수①Default → ②노출 → ③인터랙션 → ④제한 → ⑤이동 순서를 셀 수 없다. 불릿의 종류를 판별하는 규칙이 없다불릿 접두 표기 도입 검토
3마커 좌상→우하 순서HTML 프레임이 흐름 배치라 좌표가 없다. 342(UI상세설계) 스킬 검사 항목인데 못 했다프레임 내 순서 = 마커 순서로 대체 판정
4골격 상속의 정합성대표 화면 7건은 검사했지만 나머지 1,007행이 골격을 제대로 상속하는지는 검사 대상이 아니다343(설계리뷰및리팩토링) 본체
5문구 사전 일치332(컨텐츠가이드설계) 정본 문구를 그대로 썼는지 문자열 대조를 안 했다사전 정본을 기계 판독 형식으로
4번이 가장 크다. 이 검수는 슬라이드 7건의 내부 정합만 봤다. 「7건이 1,014행을 대표한다」는 주장 자체는 검증되지 않았다.
