1. 이 문서가 하는 일

OSSP는 워킹프로토타입의 목적을 동선 점검으로 규정한다 — "작성된 와이어프레임에 대해서 동선점검을 위해 inVision·POP·marvelapp 등의 툴로 작성하는 동작 가능한 프로토타입."

하는 것 (AI)하는 것 (사람)
화면 연결 맵 — 어느 요소 → 어느 화면툴에 화면 이미지 배치
동선 시나리오 — 무엇을 눌러 어디까지 가는가핫스팟·링크 연결
점검 체크리스트 — 막다른 길·순환·누락시연·관찰·기록
툴 계정·파일 위치가 확정되지 않았다. inVision·POP·marvelapp 중 무엇을 쓸지, 계정이 있는지 미확인 → [확인필요]

3. 동선 점검 체크리스트

시연 시 항목별로 ✅/⛔를 기록한다.

3-1. 폐포 — 막다른 화면이 없는가

#점검대상
C-1거래 완료 후 갈 곳이 2개 이상인가W-10
C-2모든 예외에서 복귀·고객센터로 나갈 수 있는가W-14
C-3검색 0건에서 대안이 제시되는가W-03
C-4지점 미제공 안내에서 다른 지점으로 가는가W-04
C-5대기 신청 후 상태를 조회할 수 있는가W-07 — AS-IS 막다른 길
C-6거래 중 취소하면 목록으로 돌아오는가W-08·W-09 — AS-IS 0건

3-2. 컨텍스트 — 지점을 잃지 않는가 (컨셉키워드 K1)

#점검
C-7지점 선택 후 하위 전 영역에서 컨텍스트 바가 보이는가
C-8검색 결과가 선택 지점을 반영하는가
C-9컨텍스트 없이 지점 종속 화면에 도달하면 W-01로 유도되는가
C-10지점 무관 영역(기업정보)에서 억지로 지점을 요구하지 않는가 — 컨셉키워드 K1 축 밖

3-3. 채널 동등 — 같은 일을 양쪽에서 할 수 있는가 (컨셉키워드 K3)

#점검
C-11비밀번호 변경이 MWEB에서 되는가 (AS-IS PC만)
C-12차량번호 등록이 PC에서 되는가 (AS-IS MWEB만)
C-13H.Point 전환이 MWEB에서 되는가 (AS-IS PC만)
C-14VIP프로그램이 양 채널 2Tab 동일한가 (D-3)
C-15차이가 남은 2건에 사유가 붙어 있는가 — 로그인 기록·배송조회

3-4. 순환 — 되돌이표가 없는가

#점검
C-16W-01 ↔ W-02 사이를 오가며 갇히지 않는가
C-17로그인 → 복귀가 원래 지점으로 정확히 돌아오는가
C-18예외 → 복귀 → 같은 예외 재발 시 무한 반복되지 않는가

4. 시연 시나리오 3종

프로토타입으로 처음부터 끝까지 눌러볼 경로. 각 시나리오는 위 체크리스트를 몇 개씩 소진한다.

#시나리오경로소진 체크
S-1처음 오는 사람이 지점을 정하고 행사를 본다W-02 → W-01 → W-02 → W-04C-7·C-9·C-16
S-2정원이 찬 강좌를 신청하려다 대기하고, 다른 강좌를 결제한다W-07 → 대기 → 조회 → W-07 → W-06 → W-08~10C-1·C-5·C-6·C-8
S-3모바일에서 비밀번호를 바꾸고, 없는 페이지로 들어갔다 돌아온다W-13(MWEB) → W-14 → 복귀C-2·C-11·C-15·C-18

6. ⚠️ 한계

이 문서는 프로토타입이 아니다. 동선맵과 체크리스트까지다.

동선 점검의 본질은 "눌러보니 이상하더라" 를 발견하는 것인데, 그건 실제로 눌러봐야 나온다. 문서상 폐포 점검(§3-1)은 논리적 누락만 잡고, 감각적 어색함(단계가 많다·되돌아가기 번거롭다)은 잡지 못한다.

→ §4 시나리오 3종을 실제로 시연하기 전까지 331(와이어프레임설계)은 완료로 보지 않는 것이 맞다.
