4. 정책 공백 (도출) — 212의 핵심

도출 방식: 정적 체크리스트가 아니라, 범위·화면·기능이 전제하는 규칙을 역추적했다(표준 규정). 보완한 규제 정합 6축을 질문으로 사용했다.

#공백왜 필요한가 (어느 화면·기능이 전제)미결 시 리스크참고안 제안(미확정)규제축
G1띄어쓰기 세부 규칙P-TERM-08이 "PC·MO 동일"만 규정. 341 화면명세서·332 컨텐츠가이드가 문자열을 확정해야 함채널·화면별 표기 불일치 → 오픈 후 수정 누적국립국어원 표기 원칙 + 용어사전 1종으로 고정표시·표기
G2회원 이용약관·개인정보처리방침로그인 진입 동선이 범위 내인데(P-MBR-02) 약관·방침 화면의 노출·동의 규칙이 없다. H.Point 전환 시 동의 재획득 필요 여부 불명전환 시점에 동의 없는 상태로 서비스 제공 → 법적 리스크전환 전 기존 동의 승계 가능 범위를 법무 확인 후 결정개인정보
G3문화센터 수강 신청·취소·환불 정책REQ-CU-012 온라인 신청 가이드·수강신청 화면이 존재. 취소·환불 규칙이 화면에 표시돼야 함결제·환불 관련 표시 의무 미준수기존 오프라인 수강 정책을 온라인 화면 표기로 이관전자상거래
G4마일리지 계산 주체·정확도P-MBR-07·08의 계산 규칙을 프론트가 계산하는지 백엔드 값을 표시만 하는지 미정화면 계산 시 정책 변경마다 퍼블 수정. 값 불일치 시 고객 분쟁표시 전용(백엔드 산출) 원칙 — 프론트 계산 금지등급·혜택
G5콘텐츠 게시 권한·승인 절차P-OPS-03 어드민 233건이 있으나 누가 무엇을 승인해 게시하는지 규칙이 없다(D11 미확보)어드민 설계 시 권한 모델을 임의 가정 → 재작업어드민 모듈별 권한 등급 2단(작성·승인) 최소안—
G6웹폰트 폴백 규칙P-BRD-01이 해피니스 산스를 강제하나, 미로딩·구형 브라우저(IE10) 시 대체 규칙이 없다FOUT/FOIT로 표시 붕괴. IE10에서 폰트 미적용 가능시스템 폰트 폴백 스택 지정 + 접근성 최소 가독성 확보접근성
G7등급 판정 데이터 연동 방식P-MBR-09 TCP 라운지·등급별 혜택 노출이 등급 값을 전제앱·웹 간 등급 불일치H.Point 통합회원 기준 단일 소스등급·혜택
G8접근성 준수 수준의 판정 기준P-A11Y-01이 "준수 수준"이라 했으나 무엇을 충족하면 준수인지 기준이 없다(인증이 아니므로 심사 판정도 없음)준수 여부 논쟁. 검수 불가지침 22.1의 항목 중 필수 항목 전수 통과를 내부 기준으로 확정접근성
G9연도성 콘텐츠 갱신 주체P-OPS-04가 매년 갱신을 규정하나 갱신 주체(고객 어드민 vs 수행사)가 미정오픈 후 갱신 공백어드민 연동 화면은 고객, 미연동은 별도 협의—

규제축 점검 결과: 개인정보 1건(G2)·전자상거래 1건(G3)·접근성 2건(G6·G8)에서 공백이 나왔다. 표시·표기 1건(G1)·등급혜택 2건(G4·G7). 이용약관 축은 G2에 통합. → 보완한 점검축이 공백 4건을 추가로 발견했다(초판에는 공백 섹션 자체가 없었다).
