5. 산출물 관리

  • 버전 규칙: V0.x=내부 검토본 / V1.0=고객 확정본. 확정 후 변경은 별도 이력 관리
  • 딜리버리: 산출물 도출(V0.1~0.5) → 고객사 UX 검토 → 개발 검토(V0.8~) → PM 협의체 합의·확정(V1.0)
  • 변경 관리: 설계서를 개발에 전달한 시점부터 개시. 변경분은 문서 말미 간지 추가 후 해당 장표만 복제 갱신하여 재전달
  • 작업 툴: 화면설계서=PPT / 디자인=Figma / 화면명세=Excel (124(고객요구기초분석) #1)
  • Admin 체인 분리: Admin 고유 122화면은 기획→퍼블리싱 직행. 디자인 산출물이 없는 것이 정상이며, 검수 시 결손으로 오판하지 않도록 산출물 목록에 명시 (124(고객요구기초분석) #13·#19)
