1. 마크업 원칙

  1. 시맨틱 우선 — 페이지 골격은 랜드마크로: header · nav · main · footer. main은 화면당 1개. 절 제목은 h1→h2→h3 건너뛰기 금지.
  2. 유형이 골격을 정한다 — 343(설계리뷰및리팩토링) 매핑표가 마크업 템플릿의 SSOT다. 화면 1개를 새로 짜는 게 아니라 유형 템플릿 7종을 만들고 화면은 데이터로 채운다(컨셉키워드 K2).
  3. 화면ID를 DOM에 남긴다 — <main data-screen="HDP-STR0102">. QA·운영·로그가 화면을 특정하는 단일 키. 341(화면명세서작성) 원장과 1:1.
  4. 이미지: 콘텐츠 이미지는 <img>+alt(Admin 등록 — 354(접근성가이드설계) 정책), 장식은 CSS 배경. 아이콘은 인라인 SVG + aria-hidden.

2. 클래스 네이밍 · CSS 규칙

.hd-{블록}[__{요소}][--{변형}]     예: .hd-card __title --store
상태는 클래스가 아니라 속성으로:   [aria-expanded] · [disabled] · [aria-current]
규칙이유
색·간격·크기는 토큰 변수만 — 원시 hex·px 직접 사용 금지351(스타일가이드설계) 3층 규칙. 시안 값 교체가 1파일로 끝나는 조건
셀렉터 깊이 ≤ 2 · !important 금지16개 지점 × 유형 템플릿 재사용에서 우선순위 전쟁 방지
지점 변형은 .hd-store 스코프 안에서 --hd-store-accent만351(스타일가이드설계) §6 — 지점이 바꿀 수 있는 것은 1개
상태 스타일은 :focus-visible 기준마우스 클릭에 링 안 뜨고 키보드에만 — 354(접근성가이드설계)

3. 반응형 구현

  • 브레이크포인트 1개: 1024px. PC·MWEB은 같은 마크업, 다른 배치 — 채널별 별도 페이지를 만들지 않는다(컨셉키워드 K3). 단 원장이 채널별 행을 갖는 화면(구조가 다른 548쌍)은 예외로 명시돼 있다.
  • 단위: 타이포 rem · 레이아웃 %·fr · 고정 요소만 px.
  • 터치 타깃 최소 44×44px(MWEB).

4. 리다이렉트 매핑 — 이동 38 + 제거 3

341(화면명세서작성) 원장 v1.1의 변경등급=이동 전 행을 기계 추출했다 → 리다이렉트_매핑.csv 41행 (같은 폴더).

구분건수처리
이동38301 영구 이동 — 구 화면ID → 신 화면ID. 구 URL은 개발 단계 URL 맵 확정 후 기입 [확인필요]
제거3410 또는 대체 안내 — 대체 화면 지정 필요 [확인필요]
ID 수준 매핑은 지금 확정하고 URL 수준은 미룬다. URL 체계는 서버 개발(담당 범위 밖) 결정인데, ID 매핑이 있으면 URL이 정해지는 순간 기계적으로 치환된다. 원장의 구 화면ID 보존(341 판정)이 여기서 회수된다.

9. 도출 인사이트

관찰 47 — 상류의 「보존」 판정이 세 단계 뒤에서 회수됐다

341(화면명세서작성)이 ID를 재부여하면서 구 화면ID를 버리지 않고 보존했다. 그 판정의 효용이 여기서 실현됐다 — 리다이렉트 매핑 41행이 원장에서 기계 추출됐다. 보존 안 했으면 이 표는 AS-IS를 다시 뒤지는 수작업이었다. 「지금 안 쓰는 데이터를 왜 남기나」의 답은 대부분 하류에 있다.
