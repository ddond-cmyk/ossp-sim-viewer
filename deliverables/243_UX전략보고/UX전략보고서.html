1. 배경·목적

현대백화점 공식 홈페이지 PC·Mobile Web 전 페이지의 UX/UI를 개선하는 프로젝트다(126(기초분석종합) O-1). 계약 기간 7개월, 23.1Q 오픈 목표.

이 채널은 커머스가 아니다. 브랜딩·콘텐츠 아카이빙 + 그룹사 허브 + 기업정보(IR·ESG) 가 성격이며(I1 제안서·126(기초분석종합)), 사용자 여정의 종착점은 대개 구매가 아니라 오프라인 방문 또는 정보 획득이다(241(분석종합) §1).

이 문서는 프로토타이핑 전에 방향을 선언하는 이정표다. 구체 화면 설계는 300 Define에서 다룬다.

2. 문제 요약 — 3분 안에 이해할 핵심

현행 채널의 문제는 "디자인이 낡았다"가 아니다. 구조가 두 갈래로 갈라져 있고, 반복으로 부풀어 있으며, 실패를 처리하지 않는다.

#문제실측
P1두 채널이 하나의 서비스로 작동하지 않는다진입 구조 상이(PC 1st depth 32 vs MWEB 6) · 계정 기능 결손 9건 — 모바일에서 비밀번호를 바꿀 수 없고 PC에서 차량번호를 등록할 수 없다 · 같은 브랜드가 채널마다 다른 이름(위마켓/위마캣)
P2화면이 많은 게 아니라 같은 구조가 반복된다명세 행 1,344(설계프로토타입검증) / 고유 1,003 / 본화면 574 · 지점안내 23.0% + 카드·멤버십 29.8% = 52.8% · 카드 영역은 본화면 171인데 요건은 14건
P3막혔을 때 갈 곳이 없다오류·404 화면이 명세에 0건(1,003화면 규모) · 카드신청 64화면 중 취소 경로 0건 · 수강 정원 초과가 사후 처리
P4회원 체계 전환이 설계 위에 걸쳐 있다H.Point 통합 23.1.1 — 오픈과 근접 · 전환 화면이 PC에만 존재 · 회원 메뉴 제외 경계 68화면 미정
그리고 증설이 예정돼 있다 — 더현대 대구 신규 · 브랜드 추가 입점 · ESG 콘텐츠 · 전시/공연 개선(워크숍 2차). 지금 구조로는 증설할 때마다 화면이 곱해진다.

3. UX 전략 방향 (비전)

"어느 점포인가"에서 시작해, 한 번 만든 것을 지점마다 붙이고, 어느 채널에서든 같은 일을 할 수 있게 한다. 그리고 막혔을 때 갈 곳을 먼저 만든다.

두 개의 축으로 선다.

축내용왜 이 축인가
주축 — 지점통일의 기준을 「어느 점포인가」로 둔다채널 성격이 오프라인 방문 유도이고, MWEB은 이미 지점 기점 구조(MSS)를 갖고 있다. 지점안내가 공수의 23.0%
부축 — 계정계정으로 할 수 있는 일을 채널이 가르지 않는다결손 9건이 전부 계정 영역에 몰려 있고, H.Point 전환이 이 시기에 온다

왜 하나가 아니라 둘인가: 지점(23.0%)과 카드·멤버십(29.8%)이 비등하다. 어느 하나만 축으로 삼으면 나머지 절반이 방치된다. 지점을 주축으로 두어 실행 리스크를 낮추고, 계정을 부축으로 두어 P1·P4를 함께 해소한다.

대안 검토 기록: 콘텐츠를 축으로 삼는 안도 검토했으나, 심각도 '상' 문제 9건 중 1건만 커버하고 CMS 개선이 계약 범위 밖(124(고객요구기초분석) #23)이라 실행 수단이 제한돼 채택하지 않았다.

4. 개선방향·컨셉 — 문제 → 방향 → 기대효과

컨셉키워드 K1. 「어느 점포인가」로 시작한다 (주축)

내용
문제P1 두 채널의 진입 모델이 다르다 · 검색결과가 진입 문맥을 반영하지 않는다(최대 21경로 → 화면 1)
방향양 채널 공통 진입에 지점 컨텍스트를 두고, 검색·목록·상세가 선택된 지점을 유지한다. 지점 무관 정보(IR·ESG)는 명시적으로 축 밖에 둔다
기대효과채널을 오갈 때 멘탈모델이 이어진다 · 검색 결과가 문맥을 갖는다 · 오프라인 방문 유도 + 분산 콘텐츠의 허브라는 채널 목적과 구조가 일치한다

컨셉키워드 K2. 한 번 만들고 지점마다 붙인다 (주축)

내용
문제P2 2대 영역 52.8%가 반복 구조 · 증설 예정 3건
방향지점 하위·카드 혜택을 템플릿 + 데이터로. 신규 지점·신규 브랜드가 템플릿 인스턴스로 처리되는지가 설계 합격 기준
기대효과증설해도 화면 수가 늘지 않는다 · 등급·혜택 개편이 화면 수정 없이 반영 · 운영 변경(워크숍 4건)을 구조가 흡수
유의구조는 통일하되 점포별 특성은 모듈로 표현한다. 플래그십(더현대 서울)의 개성을 닫지 않는다

컨셉키워드 K3. 계정으로 할 수 있는 일을 채널이 가르지 않는다 (부축)

내용
문제P1 계정 기능 결손 9건 · P4 H.Point 전환이 PC 전용
방향로그인·마이페이지 기능 집합을 채널 동일로. H.Point 전환 경로를 모바일에도. 채널 차이를 남기려면 결정 근거를 화면명세에 기록
기대효과"어디서 되는지"를 학습할 필요가 없어진다 · 전환 시점에 모바일 이용자가 배제되지 않는다

컨셉키워드 K4. 막혔을 때 갈 곳을 먼저 만든다

내용
문제P3 오류 화면 0건 · 취소 경로 0건
방향예외 화면군(404·권한없음·세션만료·결제실패·정원초과)을 공통 컴포넌트로 선설계. 사후 처리를 사전 경고로 전환
기대효과1,003화면이 같은 방식으로 실패를 처리한다 · 거래 완주율 개선

5. 해결대안 사례 — 제시하지 않음

OSSP는 "필요한 경우 해결대안의 사례를 포함"을 허용하나, 이 프로젝트에서는 제시할 근거가 없다.

사례 출처상태
221 서비스비교분석서축소 — 2022년 시점 경쟁사 화면 확보 실패
222 심층벤치마킹미수행 — 2022 시점 경쟁사 화면 부재. ⚠️ 원 프로젝트는 수행했다(방향성분석에 통합, 14개+ 서비스)

표준 규칙("임의 사례 날조 금지")에 따라, 레퍼런스 사례 없이 방향만 제시한다. 사례가 필요하면 고객사가 벤치마킹 대상을 지정하는 절차가 선행되어야 한다.

7. 이해관계자 우려·대응

#예상 우려이 전략의 대응
U-1"지점 중심으로 가면 카드·멤버십(최대 영역)이 밀리는 것 아닌가"그래서 계정을 부축으로 뒀다. K3가 카드·멤버십의 계정 측면을, K2가 반복 구조를 다룬다. 밀리지 않는다
U-2"모바일에 PC급 기능을 다 넣으면 무거워지지 않나"K3는 기능 집합의 동일이지 화면 구성의 동일이 아니다. 표현은 채널별로 다를 수 있고, 차이를 둘 때 사유를 기록하는 것이 규율이다
U-3"예외 화면을 먼저 만들면 눈에 보이는 성과가 늦다"사실이다(컨셉키워드 K4 trade-off에 명시). 다만 오류 화면 0건 상태로 오픈하면 운영 단계에서 더 큰 비용이 든다
U-4"회원 메뉴는 제외라고 회신했는데 K3가 성립하나"성립하지 않는다. §8-1 참조 — 이 전략의 최우선 선결 조건이다
U-5"VIP프로그램은 이미 MWEB만 개선으로 정했다"K3와 정면 충돌한다. §8-2 참조 — 재협의 대상이다

8-1. ✅ 회원 메뉴 개편 경계 — 부분 포함으로 확정

68화면을 기능 성격으로 재분류하고 C 회원정보관리만 개편 대상으로 정했다.

분류화면처리
A 법정고지·정책17손대지 않음 — 회원 체계 전환과 무관
B 인증진입21제외 — 23.1.1 H.Point 전환 시 통째로 바뀜

→ K3는 성립한다. 단 축소된 형태다. 채널 결손 9건 중 3건 해소(비밀번호 변경·H.Point 전환·차량번호) + 1건 의도적 차이 확정(로그인 기록 보기) = 4건을 다룬다. 3건은 전환·법정 사유로 범위 밖, 2건(사이트맵·웹접근성 안내)은 회원 영역이 아니라 컨셉키워드 K1·354(접근성가이드설계)로 이관.
